# HF65.24.53 — Implantação isolada do diagnóstico OIDC (sem produção)

**Estado:** instruções para homologação, NÃO representa app publicado ou autenticação validada.

## Objetivo

Verificar, com o provedor OIDC real, quais claims de sessão o Streamlit recebe.
Este aplicativo **não lê pedidos**, não consulta Supabase e não concede acesso ao
relatório comercial. A seleção visual de operador no Manager não é autenticação.

## Publicação em um NOVO aplicativo Streamlit (não substituir o atual)

1. Criar um app separado no Streamlit Community Cloud apontando para o repositório
   privado `jorgegaulke76-eng/alphafest-manager`, branch
   `hf65-24-53-conversao-comercial`, arquivo principal
   `hf65_24_53_homologacao_login.py`.
2. Anotar a URL exata do app de homologação e registrar **somente essa URL** no
   cliente OIDC do provedor (callback termina em `/oauth2callback`).
3. Configurar os valores abaixo diretamente em **Secrets do novo aplicativo
   Streamlit**, nunca no GitHub, arquivos versionados, print ou chat. Os textos
   entre sinais `<...>` são placeholders: não usar literalmente.

```toml
[auth]
redirect_uri = "https://<app-homologacao>.streamlit.app/oauth2callback"
cookie_secret = "<segredo-aleatorio-dedicado-ao-app>"
client_id = "<id-do-cliente-oidc-de-homologacao>"
client_secret = "<segredo-do-cliente-oidc-de-homologacao>"
server_metadata_url = "https://<seu-provedor>/.well-known/openid-configuration"
expose_tokens = false
```

4. Restringir o próprio cliente OIDC aos operadores de teste permitidos. **Não
   configurar `HF65_24_53_PRIVATE_REPORT_ENABLED=true` neste diagnóstico**.
5. Fazer login e conferir somente os indicadores booleanos de claims;
   não compartilhar IDs, e-mails, tokens, segredos ou respostas brutas.
6. Conferir logout, novo login, expiração e possibilidade **real de revogação**
   da sessão. `sid` presente não comprova revogação; precisa de verificação
   de servidor contra provedor/registro de sessões.
7. Se `sid`, `iat` ou `exp` faltarem, manter NO-GO, projetar uma
   verificação de sessão apropriada e testar antes de ativar a HF53.
8. Não usar endereço de produção da AlphaFest como URI de retorno e não mexer
   nos Secrets do aplicativo Streamlit atual.

- [ ] Login OIDC com usuário real de teste e sessão ativa efetivamente conferidos.
- [ ] Revogação observada no backend (não só remoção do cookie local).
- [ ] ACL por sujeito opaco configurada, sem fallback Jorge/Anna.
- [ ] Probe HTTP real executado contra Supabase `hvaptsdhaxrdxgqqpicu` com
      credencial **exclusiva de homologação**, usando backend seguro.
- [ ] Conciliação financeira E2E com dados fictícios, sem confundir status
      operacional `pago` com liquidação bancária.

independentemente dos claims. O módulo de relatório privado continua
desativado e fora do `app.py` principal.
