# Prévia online isolada — HF65.24.52

**Repositório:** público `jorgegaulke76-eng/alphafest-manager`.  
**Código:** branch `hf65-24-52-integracao-comercial`.  
**Produção:** HF65.24.51, sem alterações.

## O que já está preparado
O arquivo `scripts/hf65_24_52_online_preview.py` cria o HTML estático usando
somente os 92 produtos da vitrine pública, com o JavaScript atualizado da HF65.24.52.
Os testes do Chromium executam o fluxo de produto, WhatsApp simulado, carrinho e UTM
sem registrar eventos no Supabase nem enviar mensagens. O CI guarda esse HTML
como artefato `hf65-24-52-previsualizacao-online-html` por 7 dias.

A prévia contém aviso amarelo e proteções:
- `noindex`, `robots.txt` e `connect-src 'none'`.
- Abertura do WhatsApp **simulada**: o texto é mostrado em uma caixa e pode ser
  copiado. Nem número real nem conversa são abertos pela prévia.
- Eventos comerciais mantidos **somente em memória** no navegador.
- Não publica no Cloudflare, não altera alphafest.com.br, nem escreve dados no
  Supabase. O site de prévia não deve receber conteúdo confidencial.
- É uma página **pública**, não exige login. Não divulgar aos clientes como se
  fosse o site oficial.

## Bloqueio encontrado
Na primeira tentativa de publicação, o GitHub recusou a criação do site Pages
a partir do token automático do Actions:
`Create Pages site failed: Resource not accessible by integration`.

Isso não é erro dos produtos, do Manager nem do código comercial. A integração
não possui autorização para **ativar o Pages pela primeira vez**, embora os
testes da prévia tenham passado.

## Único passo manual necessário (sem criar serviços pagos)
Quem administra o repositório deve acessar:
1. `https://github.com/jorgegaulke76-eng/alphafest-manager/settings/pages`
2. Em **Build and deployment → Source**, selecionar **GitHub Actions**.
3. Salvar, caso o GitHub solicite, e voltar a **Actions → HF65.24.52 - Validacao comercial**.
4. Reexecutar os jobs do workflow referente à branch `hf65-24-52-integracao-comercial`.
   A implantação `deploy-online-preview` roda somente nessa ramificação, depois
   que os três jobs técnicos estiverem verdes.

**Não** é necessário mesclar a PR, publicar em produção, cadastrar chave
Supabase/Cloudflare nem fornecer senhas. O GitHub Pages oferece hospedagem sem
custo adicional para repositórios públicos nas condições do plano GitHub Free.

## Critério de liberação da URL
Compartilhar a URL somente quando o job `deploy-online-preview` terminar com
`success` e o endereço retornado pelo próprio GitHub for acessível. Não
inferir a URL a partir do nome do repositório.

Depois da ativação, conferir em um celular físico: ficha do Bubble, carrinho
com mais de um item, referência da campanha no texto **simulado**, botões
fechar/continuar, e responsividade.

A **mensagem efetivamente recebida no WhatsApp** só pode ser validada fora da
prévia isolada, em teste real autorizado; a prévia não envia mensagens.
